# 从 0 构建 一个AI Agent

随着近几年AI的兴起以及agent概念的出现，笔者发现目前网络上关于AI agent的教程纷繁复杂，虽然关于这方面的博客以及项目很多，但我发现几乎很少有项目会真正的将AI agent知识概念和实战 融合到一起来完整的学习如何构造一个agent智能体。

因此笔者创建了这个项目，将构造agent的每一个功能都拆分成一个对应的章节，章节里不仅介绍这个知识点的概念内容，还将会实现对应的项目代码，在项目里扩展实现对应功能，真正能够看到这个能力在智能体中如何发挥其作用。

一个可工作的 Agent 并不只是一个模型和一段提示词。模型负责理解和决策，Harness 负责准备上下文、组织循环、连接外部环境，并把每一步的结果交回模型。两者相互配合才会最终形成一个强大的 Agent 系统。

## 构建一个什么样的agent

本项目最终要构建的是一个“工作空间任务助手”智能体：用户提出一个工作目标后，助手能够理解任务，结合当前项目和对话信息制定下一步行动；遇到信息不足时主动向用户提问；在工作环境中执行操作并读取结果；根据反馈持续调整，直到完成任务、取消任务或安全地停止。

围绕这个目标，将会在每个章节介绍并实现一个对应的知识点，使得当下的agent变得更加强大：

- AI Harness、Agent 与大语言模型的职责边界，以及模型如何从“回答问题”变成“参与完成任务”；
- Agent Loop 的运行原理，包括目标输入、模型决策、行动执行、结果反馈和任务结束；
- 提示词、消息历史、任务状态和结构化动作协议的设计方法；
- Claude 模型接入、Anthropic Messages API 和 LangChain 模型抽象的使用方式；
- 工具调用、MCP、文件和命令执行等外部能力如何接入 Agent；
- 上下文管理、记忆、RAG 和知识检索如何帮助助手处理更长、更复杂的任务；
- Workflow 与多 Agent 的基本组织方式，以及如何拆分和协作复杂工作；
- 评测、可观测性、错误处理、安全边界和权限控制等 Agent 工程实践；

学完后，你不仅能够真的在生活中使用这个工作空间任务助手帮你工作，还能够理解其中每个组成部分为什么存在，并具备根据具体业务场景设计和扩展 Agent 系统的能力。

### 第一章：什么是 AI Harness

从模型、Harness 和 Agent 的关系开始，理解 Harness 为什么像连接模型与真实工作环境的“马鞍”，以及它如何让模型的决策能够落地执行。

目录：[01-什么是-AI-Harness](./01-什么是-AI-Harness/01-什么是-AI-Harness.md)

### 第二章：手写一个最小 Agent Loop

第二章构建了一个基于claude模型的最小任务循环。用户提交目标后，模型可以继续提问或给出最终结果；每个任务都有独立的历史记录，并支持任务取消、退出和轮数限制。

## 环境要求

- Python 3.12 或更高版本；
- [uv](https://docs.astral.sh/uv/) 包管理工具；

## 启动项目

使用 `uv` 同步项目依赖并创建虚拟环境：

```powershell
uv sync
```

配置好项目目录下的 `.env` 后，启动工作空间任务助手：

```powershell
uv run python main.py
```

离线测试：

```powershell
uv run python -m unittest discover -s tests -v
```

## 设计原则

本项目始终把“教学可理解性”和“后续可扩展性”放在一起考虑：

1. 先明确模型和 Harness 的边界；
2. 让模型层、循环层、状态层和提示词彼此分离；
3. 用稳定的动作协议连接模型输出与 Harness 行为；
4. 先使用模拟模型完成离线测试，再接入真实服务；
5. 每一章都在上一章的结构上增加能力，逐步接近生产级 Agent。
